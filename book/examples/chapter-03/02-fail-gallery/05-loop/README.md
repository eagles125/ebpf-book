# 05-loop：不可证明终止的循环（上界取自报文且无掩码）

失败画廊 card ⑤——《第 3 章 验证器与安全保障》「三、失败画廊：七类典型拒绝」3.5 节的
走读对象。本目录为 compile-only：`make` 只产出 `bad.bpf.o` / `fixed.bpf.o`，不生成
skeleton、不加载——bad 与 fixed 在 clang 层面都编译通过，差异只在加载期被
验证器（verifier）看到。

## 任务一句话

展示可终止性（termination）类拒绝：循环上界 `n` 直接取自报文内容且没有任何
掩码收窄，验证器无法证明迭代有界——加载期预期被拒；给 `n` 加一个 `& 0xF`
掩码、把上界收窄到 `n ∈ [0, 15]` 即修复。

## bad 与 fixed 差异

仅一处语义差异：fixed 给循环上界加了 `& 0xF` 掩码（上界从「任意 32 位无符号数」
收窄到 `n ∈ [0, 15]`），其余（报文界检查、循环结构、消费与返回动作）完全一致；
函数名按画廊约定固定为 `probe_bad` / `probe_fixed`。

bad 循环体的 `sum ^= i` **不是修复的一部分**：它是编译级可观测性装置——`+=` 是
线性递推，clang `-O2` 的归纳变量优化（-indvars）会算出闭式 `n*(n-1)/2`、把循环
整条消除（实测：产物里没有任何 back-edge，程序反而变成验证器可放行的形态）；
XOR 递推没有闭式，循环才得以保留（与画廊 03 的防折叠处理同一思路）。fixed 侧
同样用 `sum ^= i`，使 diff 只剩掩码这一处。

```bash
diff bad.bpf.c fixed.bpf.c   # 亲眼确认：只差一个 & 0xF
```

| 文件 | 关键形态 | 结果 |
|---|---|---|
| `bad.bpf.c` | `for (__u32 i = 0; i < n; i++)`，`n = *(__u32 *)data` 无掩码 | 编译通过；加载期预期被拒 |
| `fixed.bpf.c` | `n = *(__u32 *)data & 0xF`——上界收窄为 `n ∈ [0, 15]` | 编译通过；加载期预期放行 |

## 预期 verifier 日志关键行

（预期输出示例 / 运行级待验证；日志行随内核版本略有差异，以 5.10+ 稳定措辞为基准）

```text
infinite loop detected at insn 12
```

关键行指认「在第 12 条指令处检测到不可收敛的循环」——正好锚定本对 bad 产物中
循环回边所在（`if r1 > r3 goto -0x3`，`llvm-objdump -S` 可核验，第 12 条指令
回跳第 10 条指令）；insn 编号随产物与内核版本而异。主形态说明（5.10+ 特权
路径）：特权加载对回边本身更宽容，验证器沿循环反复模拟、状态取值域无法收敛
到「有限次迭代必退出」时，以 `infinite loop detected` 拒绝；
`back-edge from insn ... to ...` 为**非特权路径**的形态（非特权配置对回边
直接严查）。两类路径的拒绝根因相同——循环不可证明终止——拒绝本身均会发生。

## 为什么拒绝

BPF 程序跑在内核关键路径上，验证器（verifier）必须证明它**必然终止**，否则一个
被放行的死循环就把 CPU 永久卡死在软中断里——这是拒绝服务（DoS）。终止性证明
对循环的要求：要么没有回边，要么回边的迭代次数可证明有界。5.3 之前的内核
一律禁止 back-edge；5.3 起引入有界循环——验证器沿循环反复模拟，若能把变量
取值域收敛到「有限次迭代后必退出」则放行，否则拒绝（演进点，保守措辞以所用
内核文档为准）。特权档位（bpf_capable）对回边更宽容——回边本身不再一票
否决，拒绝来自状态探索不收敛（`infinite loop detected`）；非特权路径对回边
直接严查（`back-edge` 形态）。

本例的失败点在上界推导：`n` 从报文读入、无任何收窄，验证器只能推出
「[0, 2^32-1] 中的任意值」——最坏情况下 40 亿次迭代，不可证明有界。注意
「报文一般不长」在这里救不了场：攻击者完全可以构造一个 4 字节头、
`n = 0xFFFFFFFF` 的报文，按最坏情况证明的验证器必须拒绝。fixed 的 `& 0xF`
让边界推导沿位与运算传播出 `n ∈ [0, 15]`——迭代至多 15 次，可证明终止。

## 修复原则

- **上界先收窄再进循环**：`n & 0xF`（或 `min(n, 常数)` 形态）让验证器的边界
  推导拿到常数上界；掩码位数按业务需要选，上界 = 2^位数 − 1。
- 5.3+ 的有界循环不等于「随便写」：能被证明终止才放行，报文驱动的循环
  上界几乎都要掩码定界。
- 复杂迭代逻辑改用辅助函数（helper）`bpf_loop`（5.17+，演进点保守注明）把循环结构
  交给内核，或换用映射（map）迭代（`bpf_for_each_map_elem`）等有界原语。
