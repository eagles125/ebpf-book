# 02-log-diagnosis：日志诊断——从「R2 min value is negative」反推根因

《第 3 章 验证器与安全保障》「课后扩展任务」练习 2 的任务目录。练习方向与
练习 1 相反：不是「改程序看日志」，而是「按日志片段反推程序」——给定一条预期
verifier 拒绝日志，写出能复现它的最小程序。`reproduce.bpf.c` 是复现程序的
参考实现（剧透——先做后看）；本目录没有 fixed 对照，「修复」的两种形态由你
自行写出（讲解在分界线后）。本目录为 compile-only：`make` 只产出
`reproduce.bpf.o`，不生成 skeleton、不加载——程序在 clang 层面合法，拒绝发生
在加载期被验证器（verifier）看到。

## 任务

目标日志片段（预期输出示例 / 运行级待验证；即排错节第①组速查表末行收录的
关键行）：

```text
R2 min value is negative, either use unsigned or 'var &= const'
```

你的任务：

1. **只读本 README 分界线之前的内容**，从这条日志反推根因，自己写出复现程序
   （XDP 类型即可），命名自定（参考实现叫 `reproduce`）；
2. 编译自己的程序，在满足权限的内核上加载，把真实日志与本节的目标日志对照
   （运行级待验证——本目录编写环境未执行加载）；
3. **逐行解读**预期日志：`R2` 对应你程序里的哪个变量、`min value` 指什么、
   提示句的两个方向各对应什么处理；
4. 给出**两种修复**（改无符号、掩码定界），并说明各自为什么能让验证器放行。

验收标准：

- 复现程序 `make` 编译通过，且预期在加载期被拒、日志含上述关键行（运行级
  待验证）；
- 预期日志的逐行解读成文（每个成分——寄存器号、`min value`、提示句——都对应
  到程序里的具体变量与机制小节）；
- 两种修复各一份说明（或代码），讲清各自的边界推导效果。

## 提示

- 信号出自正文 2.5「有符号/无符号与掩码修正」的伏笔：验证器（verifier）给每个
  标量同时配**有符号／无符号两套上下界**（smin／smax 一族）；两套界混用会产生
  「负偏移」。先回去把这一小段读透，日志每个词都能对上机制。
- 报文指针允许算术——但**范围必须可证明非负**：一个可能为负的值被当偏移加到
  报文指针上，就是「可能向报文头前方走」。注意与画廊 3.3（03-ptr-math）区分：
  那是对报文尾界（pkt_end）做算术的**类型禁令**，本题是另一层——先想清楚
  「同类不同层」再动手（对照讨论在分界线后）。
- 日志里的寄存器号（`R2`）与逐指令轨迹随内核版本与**你自己的代码生成**而异；
  要认的是措辞主体与它背后的机制，不是具体编号（见「预期输出示例」的口径注）。
- 修复两个方向各对应 2.5 的两条处理路径——改用无符号语义让两套界对齐，或用
  掩码把取值域收窄到非负。掩码位数按业务语义选（画廊 3.5 的 fixed 版同一
  思路）。

## 预期输出示例

（预期输出示例 / 运行级待验证；完整预期拒绝日志的教学示例——外围命令回显、
逐指令行与寄存器号随 bpftool／内核版本与本产物代码生成而异，尾行关键行以
5.10+ 稳定措辞为基准）

```text
$ bpftool prog load reproduce.bpf.o /sys/fs/bpf/ch03_reproduce
; if (data + off > data_end)        /* 预期被拒：负偏移指针算术 */
9: (0f) r1 += r3
R2 min value is negative, either use unsigned or 'var &= const'
```

口径注（读这份示例前先看这里）：

- `R2` 是**教学示例口径**（与正文 2.5、排错速查表、章末任务表一致）；实际日志
  的寄存器号随代码生成而异——本目录 `reproduce.bpf.o` 实测肇事算术为
  `9: (0f) r1 += r3`，偏移标量落在 R3。你自己的复现程序看到 R2、R3 或其他
  编号都属同一信号。
- 稳定不变的认法是措辞主体 `min value is negative, either use unsigned or
  'var &= const'`：前半句指出「该寄存器的有符号最小值为负」，后半句给出两条
  修复方向。
- 逐指令行（`;` 源码回显与 `(0f)` 编码列）的格式随 log_level 档位与内核版本
  而异（2.7 与排错节第②组）；加载失败的外围错误码行随 bpftool 版本而异。
- 清理：`rm /sys/fs/bpf/ch03_reproduce`（若 pin 成功才需要——本例加载被拒，
  通常无残留）。

## 参考实现思路

**复现程序讲解**（`reproduce.bpf.c`）：

```c
if (data + 4 > data_end)          /* 先读 4 字节的合法性要单独证明 */
    return XDP_PASS;
__s32 off = *(__s32 *)data;       /* 有符号字段：smin = -2^31 */
if (data + off > data_end)        /* 预期被拒：负偏移指针算术 */
    return XDP_DROP;
```

- 第一行的界检查与画廊 3.2 同形：复现**单一**信号时，程序里其他访存都必须先
  自证合法——没有这句，第一处拒绝会是报文边界信号（`R1 offset is outside of
  the packet` 一类），目标日志就被抢占了。复现练习的一半功夫花在「让别的
  信号闭嘴」上。
- `off` 声明为**有符号** `__s32`、从报文读出（值不确定）：2.5 的标量范围跟踪
  对不确定值给最宽范围——`[-2^31, 2^31-1]`，即 smin = −2^31。有符号类型是
  整个复现的根因：换成无符号，这个信号就造不出来。
- 最后一行把 `off` 直接当报文指针偏移：off 为负时 `data + off` 指向 data
  之前——验证器拒绝一切「可能向报文头前方走」的指针算术（报文前是别的内核
  内存，走进去就绕过了报文定界）。注意这一句的比较形式虽然与界检查同形，但
  它在本程序里的作用是**消费算术结果**（两个分支返回值不同，算术可观测），
  防止 clang `-O2` 把无用算术折叠掉——画廊 03／05 的防消除意识同一出处。
  被拒的不是「缺比较」，是加法本身**范围不可证明**。

**预期日志逐行解读**（与「预期输出示例」逐行对应）：

| 日志成分 | 解读 |
|---|---|
| `; if (data + off > data_end)` | 源码行回显：verifier 把肇事指令映射回源码（BTF／调试信息在产物里，`-g` 保留） |
| `9: (0f) r1 += r3` | 肇事指令：报文指针（R1）加标量寄存器（`0f` = BPF_ADD 64 位）——教学示例口径下即「R1 += R2(off)」 |
| `R2` | 持有偏移标量 `off` 的寄存器（编号随产物代码生成而异，见「预期输出示例」口径注——本目录实测 off 在 R3） |
| `min value is negative` | 该寄存器的有符号最小值 smin < 0：`off` 是不确定的 `__s32`，边界推导给到 `[-2^31, 2^31-1]`——这条加法**可能**把报文指针推到 data 之前，按最坏情况证明（1.4）即不可放行 |
| `either use unsigned` | 修复方向一：改用无符号语义——`__u32 off` 的取值域 `[0, 2^32-1]` 以有符号视读 smin = 0，两套界对齐，加法可证明非负 |
| `'var &= const'` | 修复方向二：掩码定界——如 `off &= 0xF`，按位与沿位级抽象传播（2.5），取值域塌缩到 `[0, 15]`、smin = 0；掩码位数按业务语义选 |

**与画廊 3.3 的类型学区分**：两行日志都带 `R2` 前缀、都含「arithmetic」字样，
但属于不同机制层——

| | 画廊 3.3（03-ptr-math） | 本练习 |
|---|---|---|
| 信号 | `R2 pointer arithmetic on pkt_end PROHIBITED` | `R2 min value is negative, either use unsigned or 'var &= const'` |
| 层面 | 寄存器**类型**禁令：尾界（pkt_end）类型 `PTR_TO_PACKET_END` 不可参与算术——结构性不可证明 | 边界**推导**禁令：报文指针允许算术，但偏移取值域必须可证明非负——范围不可证明 |
| 修复 | 算术挪到报文指针上、`data_end` 全程只作比较 | 改无符号对齐两套界，或掩码收窄到非负 |

排错时先看「对**什么**指针做算术」再对号：对尾界算术查 3.3，对报文指针算术
但范围可疑查本练习——速查表第①组把两行并排收录正是为此。
